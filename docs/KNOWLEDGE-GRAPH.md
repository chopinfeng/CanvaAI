# 知识图谱

学生每讲完一道题，图谱上就多一点关于"他会什么"的东西。这是这一块存在的唯一理由——
不是为了有一张好看的网络图。

## 用的是哪份图谱，为什么

[K12-KGraph](https://github.com/haolpku/K12-KGraph)：从人教版等官方教材抽出的
K1–K12 学科图谱，**10685 个节点 / 22684 条边**，覆盖数学、物理、化学、生物。

选它而不是别的，就一条理由：**每条边都带 `evidence` 回指教材原文**。

```
← 正数（math_7a_rjb_cpt1）
   依据："如果一个问题中出现相反意义的量，我们可以用正数和负数分别表示它们."
```

讲题时要说"这一步依赖前面哪个知识点"，得说得出依据。没有 evidence 的图谱，
Agent 引用它和现编一句没有区别——而现编的那句听起来往往更顺耳，这才是危险的地方。

对比过的另一个候选 `jiangnanboy/education_knowledge_graph_app`：框架完整，
但没有开源许可声明、数据也不在仓库里，用不了。

### 许可：数据不进仓库

数据是 **CC BY-NC-SA 4.0**（署名-非商业-相同方式共享），代码是 MIT。
所以这份数据**不提交进本仓库**——那会把 NC 和 SA 传染给整个项目。
`data/` 整个在 .gitignore 里，仓库只留拉取脚本和出处。

```bash
npx tsx apps/server/scripts/fetch-kg.ts          # 一册七上数学，几百 KB，够跑通
npx tsx apps/server/scripts/fetch-kg.ts --full   # 四科完整版，约 12MB
```

服务端启动时把 `data/kg/*.json` 全部灌进去，文件名不重要。

## 掌握度：三条不肯让步的性质

写在 `packages/knowledge/src/mastery.ts`，每一条都有对应的测试。
少了任何一条，图谱都会变成一片和真实水平无关的绿。

**1. 被引导着做对 ≠ 会了。**
辅导模式下学生是被一路问出来的。把它和独立做对记一样的分，图谱三天就全绿了。
所以 guided 的加成砍掉大半，**而且有天花板**（0.55，刚好够不着"已掌握"的 0.6）——
光"给得少"挡不住累加，被问出来八次照样能爬过线。跨过那条线必须由他独立做对来完成。

实跑验证：学生 Agent 走完一整道勾股定理的题，5 问全对，最后停在 **0.55「学着呢」**，
不是「已掌握」。这正是设计要的结果。

**2. 会了也会忘。** 21 天半衰期，往 0.5（说不好）退而不是往 0 退——
很久没碰不等于不会了，只是不确定了。退到 0 会让复习建议里全是其实早就会的东西。

**3. 错一次的代价大于对一次的收益。** 栽一跤说明理解有洞，信息量比多做对一道题大。

## 三个入口

### HTTP API（给自己的前端）

| 接口 | 干什么 |
|---|---|
| `GET /kg/stats` | 装了多少、覆盖哪些学科；没装数据时告诉你怎么装 |
| `GET /kg/search?q=` | 按名字找知识点，精确命中排在包含匹配前面 |
| `GET /kg/node/:id` | 定义、例子、前置、后继 |
| `GET /kg/prereq/:id?depth=` | 学这个之前要先会什么（带教材依据） |
| `GET /kg/around/:id?learner=` | 以它为中心的一小片子图 + 这个学生的掌握度，可视化用 |
| `GET /kg/mastery/:learner` | 他哪些会哪些不会 + 下一步学什么 |
| `POST /kg/attempts` | 记一批练习结果 |

### MCP（给别的 Agent）

HTTP 那套是给我们自己的前端用的；MCP 是给 **别的 Agent** 用的——Claude Desktop、
Cursor、任何接了 MCP 的工具，都能直接问"这孩子哪块薄弱"，不用先知道我们的接口长什么样。
图谱这种东西的价值本来就在于被到处引用。

走 stdio 而不是开端口：一个学生的学习记录不该挂在公网上。

```json
{
  "mcpServers": {
    "canvai-kg": { "command": "npx", "args": ["tsx", "<repo>/apps/mcp/src/index.ts"] }
  }
}
```

六个工具：`kg_search` `kg_prerequisites` `kg_node` `kg_mastery` `kg_next` `kg_record`。

### 可视化页

```
http://localhost:5173/?view=kg&learner=<房间名>
```

一条克制：**不画整张图**。一万个节点铺开是一团毛线，好看，但没人能从里面看出任何东西。
这页始终围绕一个焦点节点看周围两跳，换焦点靠搜索或点节点。

颜色只表达一件事——这个学生在这一点上的状态（掌握 / 学着呢 / 薄弱 / 没碰过）。
学科、层级这些用大小和标签带，不往颜色上叠：颜色一多，第一眼能读出来的信息就没了。

## 图谱怎么长起来的

```
拆完题 → kg_lookup 把「勾股定理」落到真实 id
      → 每次 tutor_judge 带上 conceptIds
      → tutor_finish 成功时一次性写进掌握度
```

**攒到最后一起写**，不是每判一次写一次：中途写的话，学生半路走人会在图谱上
留下一串"被引导着做对了"的记录，而他其实并没有走完。

`conceptIds` 不填也能正常辅导，只是图谱不会长——所以提示词里把这件事说成
"图谱永远停在原地，他哪块薄弱就永远无从谈起"，而不是一句"建议填写"。
